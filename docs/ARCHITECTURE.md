# Taiwan Context AI系統架構

## 設計目標

Taiwan Context AI將模型辨識、語境推論與使用者決策分開。模型提供候選內容，Taiwan Context Engine負責證據整理、安全檢查與確認流程，避免把推測直接當成事實。

## 核心元件

| 層級 | 元件 | 職責 |
|---|---|---|
| 介面層 | 三模組前端、登入、管理中心 | 蒐集輸入、呈現候選、接收確認與授權 |
| API層 | FastAPI | 串接語音、文字、影像、回饋及審查服務 |
| 模型層 | Taiwan Tongues ASR CE | 國語、台語、客語、英語及混合語音辨識 |
| 模型層 | Qwen2.5 1.5B Instruct | 語境分析、表達改寫與多模態追問 |
| 模型層 | Gemma 3 4B | 物件、可見文字候選及影像情境分析 |
| 決策層 | Taiwan Context Engine | 候選選擇、關係證據、語意保真與風險標記 |
| 治理層 | Feedback／Review／Dataset | 授權、人工審查、去識別化與版本發布 |

## 三模態資料流

### 聲入其境

錄音或音檔經ASR產生候選逐字稿，再結合人物關係與前後文輸出字面意思、可能意境、判斷依據及建議回應。關係證據不足時顯示「不確定」，由使用者確認。

### 語你傳心

原始文字、溝通對象與表達方式送入文字模型。安全層檢查數字、日期、否定、限制語氣、台語詞彙、人物及新增資訊；候選未通過時改用保守式回退結果。

### 視界有解

圖片先由VLM分析並形成暫存影像語境。使用者後續可用錄音、音檔或文字提問；語音問題先由ASR辨識，再由文字模型結合影像語境回答。影像觀察、OCR候選與情境推論分區呈現。

## 資料治理

1. 使用者確認或修改模型輸出。
2. 使用者明確決定是否授權資料使用。
3. 待審資料由管理者核准或拒絕。
4. 核准且授權的內容成為去識別化候選。
5. 通過發布程序後寫入具版本資訊的資料集快照。

未授權修正可用於當次互動紀錄，但不得列為可發布資料集樣本。原始語音與圖片預設不寫入Git版本庫。

## 安全邊界

- 模型自報信心不是唯一判定依據。
- 推測必須與直接觀察分開。
- 人工修正不等於自動核准。
- 核准候選不等於正式發布樣本。
- 系統提供溝通建議，不代替使用者做出承諾或決定。
