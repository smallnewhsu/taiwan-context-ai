# Taiwan Context AI系統架構

## 設計原則

系統將模型輸出、語境推論、安全檢查與使用者決策分開。AI只提供候選內容；資訊不足或條件可能改變時，系統要求使用者確認。

## 核心元件

|層級|元件|職責|
|---|---|---|
|介面層|三模組前端、登入、管理中心|輸入、呈現、確認、授權及人工審查|
|API層|FastAPI|串接語音、文字、影像、回饋與資料服務|
|模型層|Taiwan Tongues ASR CE／Whisper|台灣多語及越南語辨識|
|模型層|Gemma 3 4B|語境分析、文字改寫、繁中翻譯、影像理解與問答|
|決策層|Taiwan Context Engine|人物關係、語意保真、風險警告及安全回退|
|治理層|Feedback／Review／Dataset|授權、審查、去識別化與版本發布|

## 三模態流程

### 聲入其境

錄音或音檔先產生逐字稿，再結合人物關係及前後文輸出字面意思、可能意境、判斷依據與建議回應。證據不足時顯示不確定並要求確認。

### 語你傳心

系統依原句、溝通對象與語氣產生表達建議。安全層檢查數字、日期、否定、限制條件、在地詞彙與新增資訊；風險候選不直接採用。

### 視界有解

圖片經VLM形成物件、OCR候選及情境推測。使用者可再用錄音、音檔或文字追問；回答會結合先前影像語境，並區分可見事實與推論。

## 權限與資料治理

- 一般使用者：使用三項功能、確認內容、選擇是否授權。
- 管理者：審核回饋、管理資料集、查看評測與服務狀態。
- 未授權修正不得進入資料集。
- 核准候選須經去識別化與發布程序才成為正式樣本。
- 原始語音及圖片預設不提交至Git。

## 安全邊界

- 模型信心不能取代規則檢查與人工確認。
- OCR候選、直接觀察及文化推測必須分開呈現。
- 人工修正不等於自動授權或核准。
- 系統提供溝通建議，不代替使用者承諾或決策。
