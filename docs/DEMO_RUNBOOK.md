# AI翻譯不了的台灣｜離線Demo操作手冊

## Demo前檢查

1. 接上電源並切換Windows高效能模式。
2. 關閉會大量使用GPU的瀏覽器分頁、遊戲或影像工具。
3. 確認網路中斷時系統仍可使用；Demo不依賴雲端API。
4. 確認測試音檔與圖片不含人臉、車牌、地址或個人資料。
5. 執行 `start_demo.bat`。

## 健康檢查

```bat
curl http://127.0.0.1:8000/health
curl http://127.0.0.1:8000/llm/health
curl http://127.0.0.1:8000/vision/health
ollama list
nvidia-smi
```

## 建議展示順序

### 1. 聲入其境（約40秒）

- 開啟首頁並上傳國臺混合語音。
- 展示原始辨識與臺灣語境提示候選。
- 指出系統不會偷偷改字，而是在候選不一致時要求確認。
- 手動修正後勾選資料使用同意，展示回饋進入待審流程。

講述重點：一般ASR會把臺灣生活用語轉成看似流暢但意思錯誤的國語；Context Engine的角色不是保證猜對，而是辨識風險並把決定權交還使用者。

### 2. 語你傳心（約35秒）

- 使用句子：「阿嬤，我今天工作比較忙，沒辦法回家吃飯。」
- 選擇長輩、溫暖語氣。
- 展示正常改寫。
- 再使用含時間或限制的句子，展示數字與否定保護及安全回退。

講述重點：系統不是把話寫得更華麗，而是在不改變數字、否定與限制的前提下，調整成適合對方的說法。

### 3. 視界有解（約40秒）

- 上傳一張臺灣街景或公告圖片。
- 展示四個區塊：直接觀察、OCR候選、情境推測、無法確認。
- 指出低信心文字會以警告呈現。
- 強調圖片在本機暫時處理且不永久保存。

講述重點：小型VLM可能把模糊文字說得很肯定，因此本系統不把OCR候選與文化推測當成事實。

### 4. 開源資料循環（約25秒）

- 開啟人工審查台。
- 展示待審修正、同意狀態與審查決策。
- 說明只有同意、去識別且人工核准的內容才能進入資料集版本。

## GPU記憶體注意事項

RTX 4050 Laptop GPU為6GB顯示記憶體。Demo時依序展示，不要同時重複送出語音、改寫與圖片請求。切換Ollama模型前可執行：

```bat
ollama ps
ollama stop qwen2.5:3b
ollama stop gemma3:4b
```

文字改寫前不必手動載入模型，API會呼叫Qwen；視覺分析前亦會自動呼叫Gemma。

## 備援方案

若現場模型首次載入較慢：

- Demo開始前各執行一次改寫與圖片分析完成暖機。
- 保留已完成結果的螢幕截圖或錄影，但清楚標示為備援展示。

若Ollama無法連線：

```bat
set OLLAMA_CONTEXT_LENGTH=8192
ollama serve
```

若後端無法啟動，確認使用的是專案Python：

```bat
services\asr\asr_api\Scripts\python.exe -m uvicorn backend.api:app --host 127.0.0.1 --port 8000
```

若API顯示500或503：

1. 查看後端視窗的第一個錯誤訊息。
2. 確認Ollama仍在執行。
3. 執行 `ollama ps` 與 `nvidia-smi`。
4. 停止不需要的模型後重試一次。

## Demo結束

在後端視窗按：

```text
Ctrl + C
```

再停止模型：

```bat
ollama stop qwen2.5:3b
ollama stop gemma3:4b
```
